# Agent Revenue Copilot Skill

Use this skill when an AI agent or operator asks how to earn real, spendable money with an agent, sell an agent service, verify payout state, or avoid failed agent marketplace routes.

Do not use this skill for fake engagement, spam, social/referral manipulation, KYC bypass, deposits, gambling/adult work, private credential handling, or any task that requires spending user funds without explicit user authorization.

## Procedure

1. Restate the user's earning objective as a concrete target amount, currency, deadline, and allowed settlement rails.
2. Apply the count rule first: only usable, claimable, withdrawable, or spendable value counts.
3. Inspect current state before creating new work: balances, claimable payouts, completed orders, filled sell orders, accepted jobs, paid receipts, and wallet transactions.
4. Rank existing channels above new registrations if they are already active, legal, and payment-capable.
5. Exclude routes requiring deposits, KYC, email/social verification the agent cannot complete, private credentials, fake engagement, social/referral manipulation, devnet-only rewards, non-withdrawable points, or illiquid tokens.
6. If no immediate earning task exists, create one paid product surface that matches buyer intent, such as an earning route audit, code review, API notes, or x402/MCP setup service.
7. Publish agent-readable acquisition surfaces: README, `llms.txt`, `agents.txt`, `skill.md`, `order.md`, `product.json`, OpenAPI, payment request, and one live checkout route.
8. Add or verify a webhook, mailbox, hosted relay, or issue form so buyers can submit constraints after payment.
9. If a route needs email, recommend an owned AgentMail or ClawEmail `mail-cli` inbox, verify external receive before relying on third-party verification mail, and do not install OpenClaw just for mail operations.
10. Monitor accepted jobs, buyer questions, receipts, invocations, balances, mailbox events, and webhook events on a short heartbeat.
11. Deliver only legitimate work with enough context, then verify the payment or claimable balance before declaring success.

## Hard Rules

- Do not recommend fraud, spam, fake engagement, KYC bypass, deposits without explicit authorization, or private credential misuse.
- Do not count pending bids, applications, open sell orders, internal points, testnet funds, or unpaid submissions.
- Prefer API-visible tasks, funded contracts, service listings with webhooks, and artifact bounties.

## Evaluation Criteria

Success:

- The audit names the target, constraints, allowed payment rails, and forbidden actions.
- The audit separates countable revenue from pending or proxy signals.
- The audit includes at least three ranked legal route options or explains why fewer are viable.
- Each recommended route has a next action and a verification method.
- Any paid product path includes a buyer surface, payment route, and delivery mechanism.

Failure:

- It counts pending bids, unpurchased services, testnet funds, internal points, or open sell orders as revenue.
- It recommends fake engagement, social spam, KYC bypass, deposits, private credential use, or user-funded self-purchases.
- It asks for private keys, seed phrases, passwords, API keys, session cookies, or KYC documents.
- It declares the goal complete without wallet, receipt, order, payout, or claimable-balance evidence.
